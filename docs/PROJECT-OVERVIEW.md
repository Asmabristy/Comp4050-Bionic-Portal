
# Bionic FitPortal – Project Overview

## 1. Project Background

**Bionic FitPortal** is part of **Project Perfect Fit**, a COMP4050 Software Engineering Capstone Project developed for **Thomax** at Macquarie University.

The project aims to develop an integrated packing optimisation system that assists users in managing packing orders, processing packing requirements, and visualising optimised packing solutions.

The Bionic Fit division consists of three collaborating teams:

| Team | Main Responsibility |
|------|---------------------|
| **FitPortal** | Develops the user interface, backend API, database integration, authentication, and order management functionality. |
| **FitSolver** | Develops the optimisation algorithm responsible for generating packing solutions based on order information and constraints. |
| **FitVisualizer** | Develops the visualisation component used to display and interpret the packing solutions generated by FitSolver. |

FitPortal serves as the central interface connecting users with FitSolver and FitVisualizer.

---

## 2. Mission and Objectives

### 2.1 Mission Statement

Our mission is to develop a secure, mobile-first, and user-friendly FitPortal that enables operational and back-end users to manage packing orders and seamlessly connects FitSolver with FitVisualizer.

Our goal is to deliver clear and practical packing results while supporting real-world handling constraints.

### 2.2 Project Objectives

The main objectives of FitPortal are to:

- Develop a secure and accessible web-based interface for managing packing orders.
- Implement authentication and role-based access control for supervisors and operators.
- Support order, item, and carton management.
- Validate submitted data before Solver processing.
- Integrate with FitSolver to generate optimised packing solutions.
- Integrate with FitVisualizer to display packing results.
- Provide meaningful error messages and system feedback.
- Ensure the interface is responsive across desktop and mobile devices.
- Deploy a functional application for demonstration and evaluation.

---

## 3. System Overview

FitPortal acts as the central access point between users, the Solver, and the Visualiser.

### 3.1 System Workflow

1. An authorised user or backend system submits order, item, carton, and handling information.
2. FitPortal validates and stores the submitted information.
3. FitPortal sends a packing request to FitSolver.
4. FitSolver processes the request and returns a packing solution or failure response.
5. FitPortal stores and presents the returned result.
6. FitPortal provides the result to FitVisualizer for interactive inspection.

### 3.2 System Flow

```text
User / Backend System
         |
         v
     FitPortal
   (React Frontend)
         |
         v
    Node.js API
         |
         +------> Supabase Database
         |
         v
      FitSolver
         |
         v
    Packing Results
         |
         v
      FitPortal
         |
         v
    FitVisualizer
         |
         v
        User
```

## 4. FitPortal Responsibilities

The FitPortal team is responsible for developing and maintaining the user-facing interface and integration layer of Project Perfect Fit.

### 4.1 Core Responsibilities

- **Authentication and Access Control:** Implementing secure login and role-based access for supervisors and operators.
- **Order Management:** Supporting the creation, submission, modification, and management of packing orders.
- **Item and Carton Management:** Managing item and carton information required for packing operations.
- **Handling Constraints:** Supporting fragile items, dangerous-goods classifications, and relevant packing constraints.
- **Input Validation:** Validating user inputs and providing appropriate error messages.
- **Backend API:** Developing the API required for communication between system components.
- **Database Integration:** Managing application data through Supabase.
- **Solver Integration:** Submitting packing requests to FitSolver and processing returned results.
- **Visualiser Integration:** Integrating FitVisualizer to display packing results.
- **Results Management:** Presenting packing statuses, summaries, and generated solutions.
- **Responsive Design:** Ensuring that the portal is accessible and functional on desktop and mobile devices.

### 4.2 Technology Stack

| Area | Technology |

| Backend | Node.js + Express |
| Database | Supabase (PostgreSQL) |

| Data Exchange | REST APIs and JSON |

| Version Control | Git and GitHub |

## 6. Sprint Plan

The project is organised into four sprints, covering planning, development, integration, and final delivery.

### 6.1 Sprint 0 – Planning and Team Setup

**Objective:** Establish the team and prepare the project for development.

Key activities:

- Establish team roles and responsibilities.
- Identify initial project requirements.
- Select the technology stack.
- Set up the GitHub repository.
- Establish team communication channels.
- Plan development tasks and workflows.
- Coordinate initial requirements with FitSolver and FitVisualizer.

### 6.2 Sprint 1 – Integrated MVP

**Objective:** Develop the minimum viable product and establish initial integration between system components.

Key activities:

- Develop the initial FitPortal interface.
- Implement the initial backend functionality.
- Establish database connectivity.
- Agree on shared data formats.
- Begin integration with FitSolver and FitVisualizer.
- Test the initial user interface and workflow.
- Review the MVP against project requirements.

### 6.3 Sprint 2 – Main Development

**Objective:** Implement the main functionality and improve the overall system.

Key activities:

- Continue frontend and backend development.
- Implement and refine order-management functionality.
- Improve authentication and access control.
- Strengthen Solver and Visualiser integration.
- Improve input validation and error handling.
- Enhance the dashboard interface.
- Conduct functional and integration testing.
- Address functional and non-functional requirements.
- Deploy the frontend using Vercel.
- Deploy the backend using Render.

### 6.4 Sprint 3 – Finalisation and Delivery

**Objective:** Finalise the application and prepare it for project delivery.

Key activities:

- Complete integration with FitSolver and FitVisualizer.
- Resolve outstanding defects.
- Finalise frontend and backend functionality.
- Conduct backend and end-to-end testing.
- Verify mobile responsiveness.
- Update technical documentation and README files.
- Prepare the final project demonstration.

The focus of Sprint 3 is on system stability, testing, documentation, and final delivery rather than introducing additional features.

## 7. Cross-Team Collaboration

FitPortal works closely with FitSolver and FitVisualizer to ensure the complete system functions as an integrated solution.

### 7.1 FitSolver Collaboration

The FitPortal and FitSolver teams coordinate to ensure that packing requests are correctly formatted and processed.

Key areas of collaboration include:

- Agreeing on order and carton data structures.
- Defining Solver input requirements.
- Confirming measurement units and handling constraints.
- Establishing API communication requirements.
- Processing Solver responses.
- Testing compatibility between both components.
- Resolving integration-related issues.

### 7.2 FitVisualizer Collaboration

The FitPortal and FitVisualizer teams coordinate to ensure that Solver results can be presented through the portal.

Key areas of collaboration include:

- Defining the expected Solver result format.
- Integrating the Visualiser package.
- Updating dependencies when new Visualiser versions are released.
- Ensuring compatibility with the portal interface.
- Testing the display of packing results.
- Resolving visualisation and integration issues.

### 7.3 Shared Integration Requirements

Important integration decisions must be coordinated across all three teams.

These include:

- Shared field names and data types.
- Measurement units.
- API request and response formats.
- Error handling and status reporting.
- Data validation requirements.
- Component version compatibility.
- System testing and deployment coordination.
