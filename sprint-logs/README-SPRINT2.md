
# Bionic Portal – Sprint 2 
For the project overview, team roles and sprint plan, see [PROJECT-OVERVIEW.md](./PROJECT-OVERVIEW.md).

---

## 1. Sprint Overview

Sprint 2 focused on improving the functionality, usability, and integration of the Bionic FitPortal system. Building on the initial minimum viable product (MVP) developed during Sprint 1, the team worked on refining the user interface, implementing additional order-management features, strengthening integration with FitVisualizer, and deploying the updated application.

The sprint also involved code refactoring, improvements to user account management, functional testing, and merging development changes into the main GitHub branch.

### Sprint Objectives

The main objectives of Sprint 2 were to:

- Integrate FitVisualizer into the portal.
- Implement user account deletion functionality.
- Refactor existing code to improve maintainability.
- Provide access to raw Solver output results.
- Add carton deletion functionality.
- Improve and redesign the user interface.
- Merge the `ui-refactor` branch into `main`.
- Deploy the updated application.
- Conduct functional and usability testing.

---

## 2. Development Activities

### 2.1 FitVisualizer Integration

The team integrated the FitVisualizer component into FitPortal to improve how packing optimisation results are presented to users.

This integration allows users to view a visual representation of packing solutions generated by FitSolver rather than relying solely on raw output data.

Key activities included:

- Integrating the updated Visualiser package into the portal.
- Connecting Solver results with the Visualiser component.
- Ensuring compatibility with the existing frontend.
- Improving the accessibility and presentation of packing results.

**Outcome:** FitVisualizer was integrated into the portal, improving the presentation and interpretation of Solver results.

### 2.2 User Account Deletion

User account deletion functionality was implemented to improve account management within FitPortal.

This feature extends the existing authentication and access-control system by supporting the removal of user accounts.

Key activities included:

- Implementing account deletion functionality.
- Integrating the feature with the existing authentication system.
- Supporting the management of user accounts.
- Ensuring account deletion functionality aligns with the application's access-control requirements.

**Outcome:** User account deletion functionality was added to improve account management.

### 2.3 Code Refactoring

Existing code was refactored to improve readability, maintainability, and overall code organisation.

The refactoring process focused on simplifying existing implementations and improving code structure without unnecessarily changing application behaviour.

Key activities included:

- Reviewing existing frontend and backend code.
- Improving code structure and organisation.
- Reducing repetitive or unnecessary code.
- Improving consistency across application components.
- Supporting easier maintenance and future development.

**Outcome:** The codebase was refined to improve maintainability and support continued development.

### 2.4 Raw Solver Output Results

A new button was added to the portal to allow users to access raw Solver output results.

Previously, accessing detailed Solver output could require checking backend logs or terminal responses. This improvement makes the raw results more accessible through the web interface.

Key activities included:

- Adding a button to view raw Solver results.
- Connecting the button to the Solver output.
- Improving access to detailed optimisation information.
- Supporting verification and troubleshooting of Solver responses.

**Outcome:** Users can access raw Solver results directly through the portal interface.

### 2.5 Carton Deletion Functionality

Carton deletion functionality was added to improve order management and provide users with greater flexibility when preparing packing orders.

This feature allows users to remove cartons from an order when changes are required.

Key activities included:

- Adding carton deletion controls.
- Implementing carton removal functionality.
- Updating the user interface to reflect changes.
- Improving the overall order-management workflow.

**Outcome:** Carton deletion functionality was implemented, allowing users to manage packing orders more effectively.

### 2.6 User Interface Refactoring and Improvements

The team refined the existing FitPortal interface to create a more professional, consistent, and user-friendly design.

The redesign focused on reducing generic, template-like design elements and improving the overall visual presentation of the dashboard.

Key activities included:

- Refining the dashboard layout.
- Improving component styling and consistency.
- Enhancing readability and visual clarity.
- Improving the organisation of information.
- Refining buttons, navigation, and interactive elements.
- Supporting a cleaner and more intuitive user experience.

**Outcome:** The portal's interface was improved to provide a more polished, consistent, and practical user experience.

### 2.7 Branch Merging and Deployment

Following the UI improvements, the `ui-refactor` branch was merged into the `main` branch to integrate the updated interface with the main application.

The team also deployed the updated portal using Vercel for the frontend and Render for the backend.

Key activities included:

- Merging `ui-refactor` into `main`.
- Verifying that the merged changes were successfully integrated.
- Deploying the updated React frontend through Vercel.
- Deploying the Node.js backend through Render.
- Configuring the application for the deployed environment.
- Reviewing the deployed application for issues.

**Outcome:** The updated application was successfully merged into the main branch and deployed.

### 2.8 Functional and Usability Testing

Testing was conducted throughout Sprint 2 to verify implemented functionality and identify potential issues.

The testing process focused on ensuring that the application remained functional following the integration of new features and UI changes.

Key activities included:

- Testing frontend functionality.
- Checking navigation and interactive elements.
- Verifying order-management features.
- Reviewing carton deletion functionality.
- Checking the updated dashboard interface.
- Testing the behaviour of newly implemented features.
- Identifying bugs and usability issues.
- Supporting quality assurance before finalisation.

**Outcome:** Functional and usability testing supported the identification of issues and verification of newly implemented features.

## 5. Challenges and Improvements

### 5.1 Cross-Team Integration

Integrating FitVisualizer required coordination between FitPortal and FitVisualizer to ensure compatibility between system components.

Maintaining consistent data structures and ensuring that Solver results could be correctly interpreted by the Visualiser were important considerations.

### 5.2 User Interface Consistency

The original interface required refinement to achieve a more professional and consistent design.

The team addressed this by improving the layout, component styling, readability, and overall user experience.

### 5.3 Branch Management and Deployment

Merging UI changes into the main branch required ensuring that the updated interface remained compatible with existing functionality.

Deploying the frontend and backend also required correct configuration of the application and communication between the hosted services.

### 5.4 Testing and System Stability

As more functionality was introduced, maintaining system stability became increasingly important.

The team conducted functional testing throughout the sprint and identified comprehensive backend and end-to-end testing as priorities for the final stage of development.
